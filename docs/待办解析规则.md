# 待办自然语言解析规则

入口：`kb/nlp_parser.py::parse_task_from_text(text)`，被快速待办预览
（`routes/tasks_api.py::api_quick_task_preview`）与待办页面复用。

输出字段：

| 字段 | 含义 |
|---|---|
| `title` | 标题 |
| `description` | 原文 |
| `category` | 分类：考试/培训/会议/工作/个人 |
| `start_time` / `end_time` | 起止时间 |
| `assignees` / `is_all` | 负责人名单 / 是否全员 |
| `recurrence` / `recurrence_text` / `recurrence_count` / `recurrence_interval_days` | 周期信息 |
| `sessions` | 多场次列表（每场 `label/start/end`） |

时间源统一为 `core.timeutil.cn_now()`。

## 一、标题提取 `extract_title_from_text` → `_extract_title_base`

按优先级依次尝试，命中即返回（截断 80 字）：

| 优先级 | 规则 |
|---|---|
| 1 | 首个 `【…】` 内容 ≥5 字 → 采用；否则取 `】` 后正文（先剔除 URL、`@xx`、屏蔽词） |
| 2 | 解析标题 <6 字时，回退取 `主题:xxx` 冒号后的文字 |
| 3 | `动词:内容` 结构取冒号后（如 `提醒:明天交周报` → `明天交周报`），长度 4–60 |
| 4 | 引号 `""　「」` 内的 4–60 字 |
| 5 | 按 `。！，,；;——— 换行` 切分，取首个符合长度的片段 |
| 6 | 截断 `从/到/截止/提交/发给/给/指派给/分配给/完成` 之后内容 |
| 7 | 去掉 `请各…，` 前缀后逐级降级 |
| 8 | 兜底 `未命名待办` |

屏蔽词 `TITLE_BLOCK_WORDS`：
`反馈 / 链接 / 腾讯文档 / https / http / 通知 / 请各位 / 请各处室 / 请提醒 /
请传达到位 / 请确认 / 请各部门 / 请各单位`

## 二、分类 `category`

优先级：**考试 > 培训 > 会议 > 工作 > 个人**，判定顺序：

1. 标题以「会」结尾 → **会议**
2. 正文含 `会议[时地内]` → **会议**
3. 标题命中关键词（按字典序首次命中即定）
4. 正文关键词计数投票，平票取首命中
5. 均无 → 默认 **工作**

关键词组：

| 分类 | 关键词 |
|---|---|
| 考试 | 考试 测验 笔试 月考 中考 高考 期中考 期末考 考级 考核 答辩 |
| 培训 | 培训 训练 课程 集训 学习班 研修班 岗前培训 入职培训 技能提升 培训会 |
| 会议 | 会议 开会 例会 晨会 周会 月会 评审会 研讨会 复盘 站会 宣贯 |
| 工作 | 工作 项目 待办 报告 汇报 方案 开发 测试 上线 需求 周报 月报 |
| 个人 | 个人 学习 读书 运动 健身 购物 家务 休息 娱乐 游戏 电影 旅游 |

## 四、时间解析

优先级：**JioNLP 语义解析 → 旧正则候选链 → 兜底默认**。

### 4.1 JioNLP 路径 `_parse_timespan_jionlp`

`KB_TIME_PARSER=legacy` 时跳过。每个时间实体先做**噪声规范化**：

- 剔除纯年份 `2026`、`年+裸数字`（如标题「2026年1024程序员节」拆出的 `2026年1024`）
- 剔除标题 `【】` 内未闭合的实体
- 剔除连续 **≥6 位纯数字**（会议号/入会密码/工号，如 `920200844430`、`202610`），
  但保留合法紧凑日期 `YYYYMMDD`（如 `20261017`）
- 无时段词（上午/下午/晚上…）且无 `X点/X:XX` 的 **point**，默认 `09:00`
  （若有结束则 `17:00`）
- 类型判定：
  - `range`：形如 `14:00-16:00`（`-—~至` 连接）
  - `deadline`：`…前 / …之前 / 截止`
  - 其余 `point`
- 周规则：`周X/星期X` 已过去且无「上周/之前」→ 顺延到未来；
  **显式日期中的周X（如 `8月25日（周二）`）只当注释，不顺延**
- 显式区间补救：jionlp 把 `15:00-16:00` 拆成两个独立 point 时，扫描原文重组 range
- 模糊实体（`definition=blur`，如「中期/年底」）：存在准确实体时剔除，
  避免宽泛跨度覆盖明确日期
- 「全天」实体：并入最近的日期实体并扩为 `00:00–23:59`
- **无日期纯时刻归属**：括号内 `14:00-17:00` 这类无日期时刻会被 jionlp 挂到
  「今天」，按位置重新归属到其前最近的明确日期实体（防止分场次时间覆盖活动日期）

合并策略：

| 情况 | start | end | 备注 |
|---|---|---|---|
| 有 range | 最早区间起 | 最晚区间止 | 标记 `explicit`，即使已开始/已结束也原样保留 |
| 无 range 有 deadline | 截止前最近的未来 point | 最晚截止 | |
| 仅 point | 最早未来时刻 | 最远时刻 | |
| end < now 且非 explicit | — | 置空 | |

### 4.2 旧正则回退 `_find_all_datetime_candidates` / `detect_deadline_from_text`

- 相对日：`今天/今[天日]`、`明天/明[天日]`、`后天/后[天日]`、`大后天`
- 周：`下下X`、`下X`、`这/本周X`
- 绝对：`YYYY年M月D日`；`M月D日`（无年且已过 → 顺延一年）
- 时刻：`上午/下午/晚上 + X点/X:XX/X时`
- 日期与时刻配对 + 单独时刻配对当天；去重排序取**最晚**为 `end`
- `detect_deadline_from_text`：`到/截止/至/—/~` 之后取时间，默认 `18:00`

### 4.3 无任何时间词兜底

- 无候选 → 默认 `now + 7天 18:00`
- 文本含 `N天` → `now + N天`；含 `N周` → `now + N周`

### 4.4 辅助函数

- `_parse_time(text)`：返回 `(时,分)`；**冒号按 24 小时制**，`点/时` 识别
  `上午/下午/晚上`；无时段且 `时<7` → +12 点
- `parse_chinese_datetime`：旧接口，当前未被调用

## 五、周期/重复 `recurrence`

| 文本 | 类型 | 间隔 | 次数 |
|---|---|---|---|
| 每天/每日/天天 | daily | 1 | 10 |
| 每周X | weekly | 7 | 4 |
| 每N周 | weekly | N×7 | 4 |
| 每N个月 | monthly | N×30 | 3 |
| 每N年 | yearly | N×365 | 2 |

> 多场次拆分触发时，周期字段全部清零。

## 六、多场次拆分 `_extract_sessions`

触发条件：出现 **≥2 处** `第X期/届/场/次/轮/节/讲/阶段/段/批/天`
（`第X` 后紧跟中文/引号则不触发）。

- 每个「第X」段落内**每个日期各拆一场**（如「任选其一」多日期）
- 无年份 → 当年；已过 → 顺延一年
- 缺结束时间 → `+1 小时`；结束 ≤ 开始 → `+1 天`（跨午夜）
- `X月X日前` 截止型 → 当日 `08:30–17:30`
- 段落内既无日期也无截止词 → **空场**（`start=None`，待确认页手填）
- 触发后：主 `start_time/end_time` 取**第一场**

---

## 七、落库前处理（`routes/tasks_api.py`）

- `start` 缺省 = `now`；`end` 缺省 = `start + 1天`；`end <= start` → `+1 小时`
- 周期任务若被解析成跨天 → 收敛为 `1 小时`
- `sessions`：每场生成一个待办，标题追加 `（第X期）`；空场时间留空
- 结合 `category`、`assignees`、`is_all` 做相似待办查重

| 会议通知：`会议时间：2026年8月25日（周二）08:40-10:00` | 分类 `会议`、start `2026-08-25 08:40`、end `2026-08-25 10:00` |

| `系统升级年底前完成上线` | `end_time` 不为空（模糊兜底） |

### 8.7 多场次 `sessions`（`第X期/阶段` ≥2）

输入：

```
第一期：2026年8月28日14:30-16:30
第二期：2026年9月3日14:00-18:00
第三期：2026年9月4日14:30-15:30
```

结果：

| 项 | 值 |
|---|---|
| 场次数 | 3（labels：`第一期/第二期/第三期`，按序） |
| 第一场 | `2026-08-28 14:30 – 16:30` |
| 第二场 | `2026-09-03 14:00 – 18:00` |
| 第三场 | `2026-09-04 14:30 – 15:30` |
| 主时间 | 取第一场 `start/end` |
| 周期 | 清零（`recurrence_interval_days=0`、`count=0`） |
| 单场次 | 不触发拆分，`sessions=[]`（预览接口回退为普通任务） |

其它场次规则：

| 输入 | 结果 |
|---|---|
| `第一期：9月7日上午9:00` / `第二期：9月8日晚上8:00` | start 时分别为 `9`、`20` |
| `第一阶段：9月30日前集中补学。` / `第四阶段：9月20日前完成材料。` | `09-30 08:30–17:30`、`09-20 08:30` |
| 阶段内无时间（`第四阶段：围绕主题交流研讨。`） | 空场 `start=None` |
| `第一期：…14:30-16:30`（仅一场） | `sessions=[]` |
| `第一期：2026年13月40日99:99` / `第二期：2026年9月3日14:00-18:00` | 非法日期跳过后仅剩 1 场 → `[]` |
| 跨午夜 `23:00-01:00` | end 为次日 `01:00` |
| 同段多日期 `…9月…日下午3:00、…日上午9:00，任选一天` | 拆成多场（各日期一场） |

### 8.8 边界与回归

| 场景 | 结果 |
|---|---|
| 标题 `2026年1024程序员节` 中的 `1024` | 不作为日期 |
| `会议号：920200844430` / `：202610` | 不产出时间 |
| `20261017`（合法 `YYYYMMDD`） | 正常解析为日期 |
| 括号内无日期时刻（`14:00-17:00`） | 归属同句前最近日期，不落回当天 |
| `每天/每周X` + 多场次 | 多场次优先，周期清零 |

## 九、易错场景速查

1. **标题噪声**：`2026年1024程序员节` 的 `1024` 不是日期。
2. **长数字**：会议号/密码/工号 ≥6 位纯数字不参与解析（合法 `YYYYMMDD` 除外）。
3. **无日期分场次时间**：归属同句前文日期，不落回当天。
4. **模糊时段**：`中期/年底` 不覆盖明确日期。
5. **显式区间**：已开始/已结束也原样保留，不置空、不顺延。
6. **显式日期+周注**：`8月25日（周二）` 以日期为准，不顺延到下周。
7. **无时间词**：兜底 `now + 7天 18:00`，保证 `end_time` 非空。
